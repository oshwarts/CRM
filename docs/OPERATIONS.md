# תפעול ותקלות

מסמך למי שמחזיק את המערכת: מה לבדוק, איך מתאוששים, ומה המגבלות של התוכנית החינמית של Supabase.

## מצב המערכת

הגדרות ← **בריאות המערכת** (מנהל): נפח מסד הנתונים והאחסון מול המכסה, תקלות שמשתמשים נתקלו בהן ב-24 השעות וב-7 הימים
האחרונים, מצב הגיבוי, וגודל הטבלאות. לבדוק פעם בשבוע.

## גיבוי ושחזור

- **גיבוי ידני**: ניהול מערכת ← גיבוי ← "הורדת גיבוי". קובץ JSON עם כל הטבלאות (רשימת הטבלאות נלקחת מהמסד).
  הקובץ כולל פרטי מטופלים: לשמור במקום מאובטח של החברה. תזכורת מופיעה ב"דחוף עכשיו" אחרי 7 ימים.
- **קבצים** (מידע קליני, פרויקטים, תמונות): ב-Storage, אינם בקובץ הגיבוי. להוריד מדי פעם מ-Supabase ← Storage.
- **שחזור**: ליצור פרויקט Supabase, להריץ את המיגרציות לפי הסדר, ולטעון את הנתונים מקובץ הגיבוי לפי סדר הטבלאות (טבלאות הפניה קודם).
- בתוכנית Pro יש גיבוי יומי אוטומטי ושחזור לנקודת זמן (Supabase ← Database ← Backups).

## מגבלות התוכנית החינמית

- הפרויקט **נעצר אחרי שבוע בלי פעילות** (ההפעלה מחדש מלוח הבקרה לוקחת דקות).
- 500MB מסד נתונים, 1GB אחסון, 5GB תעבורה בחודש, קובץ בודד עד 50MB.
- אין גיבוי אוטומטי, ואין הגנה מפני סיסמאות שדלפו (Leaked password protection).
- מומלץ לעבור ל-Pro כשהמערכת משמשת את כל הצוות ביום-יום.

## פעולות שגרתיות

| מה | איך |
|----|-----|
| משתמש חדש | נרשם במסך הכניסה, מנהל מאשר ב"ניהול מערכת" ← משתמשים |
| משתמש שעזב | "ניהול מערכת" ← משתמשים ← להשבית (הנתונים נשארים) |
| איפוס סיסמה | המשתמש: "שכחתי סיסמה" במסך הכניסה. הקישור חוזר לאתר ומציג בחירת סיסמה |
| קובץ גדול (25–50MB) | בקשה מופיעה ב"דחוף עכשיו" ובהגדרות ← אישורי העלאה |
| יצירת שאלות בבינה מלאכותית | כבויה. להפעלה: הגדרות ← בריאות המערכת, ומפתח `ANTHROPIC_API_KEY` ב-Supabase ← Edge Functions ← Secrets |
| שינוי שלבי משפך / סף תקוע | הגדרות ← רשימות ← שלבי המשפך |
| בקשת סוכן להליך חדש | מופיעה ב"דחוף עכשיו" ובהגדרות ← הליכים: מאשרים (אפשר לתקן שם ולבחור הליך אב) או דוחים. הליכים נערכים רק על ידי מנהל; הליך יכול לכלול תתי-הליכים (רמה אחת) |
| הצעה לשיפור המערכת | כל משתמש: לוח הצד ← כפתור המראה ← "הצעה לשיפור המערכת". ההצעות מגיעות רק למשתמש שמסומן is_developer (ניהול מערכת ← הצעות לשיפור, וב"דחוף עכשיו"), והוא עונה בסטטוס ותשובה קצרה. ההצעות לא יוצאות מהמערכת (אין מייל) |
| ימי מרפאה | רופא ← בתי חולים ומרפאות: ימים לכל בית חולים (בטופס העריכה) ומרפאות פרטיות עם כתובת. בעמוד בית החולים: "מרפאות לפי יום" |

הגדרת **Auth ← URL Configuration** ב-Supabase: Site URL וכתובת האתר ב-Redirect URLs, אחרת קישור איפוס הסיסמה לא יחזור לאתר.

## פריסה ושינויים

1. שינוי קוד: `npm run check` (lint + בדיקות + בנייה), ואז push ל-`main`. Vercel מפרסם לבד.
2. שינוי מסד: קובץ חדש ב-`supabase/migrations/` (המספר הבא), הרצה, ובדיקת הרשאות ב-`supabase/tests/smoke.sql`.
3. אחרי פריסה: לרענן את האפליקציה (בטלפון לסגור ולפתוח). גרסה חדשה מזוהה לבד והדף נטען מחדש פעם אחת.
4. כותרות האבטחה (`vercel.json`): אם מוסיפים סקריפט inline ל-`index.html`, יש לעדכן את ה-hash ב-CSP (בדיקה אוטומטית ב-`npm test` תיכשל אם שכחתם).

## כשמשהו לא עובד

1. **אף אחד לא נכנס / שגיאות חיבור**: לבדוק שהפרויקט ב-Supabase לא נעצר (התוכנית החינמית).
2. **משתמש אחד בלבד**: לבקש רענון/סגירה ופתיחה של האפליקציה; לבדוק בבריאות המערכת אם נרשמה תקלה על שמו.
3. **שמירה נכשלת**: הודעה מפורטת מופיעה על המסך; בדרך כלל חיבור או הרשאה. יומן הפעולות (ניהול מערכת) מראה מי שינה מה.
4. **שינוי "נעלם"**: לבדוק ביומן הפעולות. שני אנשים שערכו את אותו שדה מקבלים שאלה לפני דריסה.
5. **תקלה אחרי גרסה חדשה**: Vercel ← Deployments ← Promote של הפריסה הקודמת.
